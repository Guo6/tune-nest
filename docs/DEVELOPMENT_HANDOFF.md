### 修复打包阶段的自动化验证

- 修复设置页「测试实际调用」报 `invalid args 'body' for command 'request_ai': missing field 'maxTokens'`。前端传入嵌套 `body.max_tokens`，Rust 的 `ChatRequest` 使用 camelCase 命名，旧代码无法解析；请求在调用上游前就被拒绝。现在明确兼容 `max_tokens`，保留 `maxTokens`，参数仍为必填。
- 原有前端 AI 测试覆盖扩展 HTTP 路径，Rust 真实请求测试直接构造结构体，均未覆盖这段反序列化，不能据此宣称桌面按钮完整验收。本次新增共享 `tests/fixtures/ai-ipc-request.json`，前端使用实际设置组件及桌面桥接验证三个渠道的调用参数，Rust 用同一份请求验证反序列化和上游 payload。新测试修复前已复现相同缺字段错误，修复后通过。
- 修复打包阶段有 48 项前端 / 组件测试、7 项 Rust 单元测试通过，当时尚未重复执行真实模型调用；随后补充的真实 release 程序调用结果见上方，勿将两个验证阶段混淆。扩展、前端生产构建及 Rust 格式检查通过。v0.1.12 为 Windows x64 测试安装包，既有 QQ / macOS 验收缺口不变。

## 2026-11-06：v0.1.11 智能分类前 AI 配置引导

- 首页、桌面侧栏进入智能分类时检查当前 AI 渠道的密钥配置状态及启用状态；齐全时直接进入歌单选择，不发出模型请求。不把其他渠道已配置视为当前渠道已配置。
- 未就绪时显示配置建议，提供「去配置 AI 渠道」和「暂不配置，继续分类」。设置在流程内打开，「保存并继续分类」校验配置后回到原流程，保留歌单、歌曲和分类维度。
- 临时跳过仅对本次任务传递 `rulesOnly`，不写回或关闭已保存的 AI 设置；桌面和扩展均会执行规则分类，甚至设置读取失败时也可跳过。不跳过的任务在实际分类前再检查一次，避免途中配置变化。
- React 组件和入口集成测试覆盖三个渠道已配置、未配置、AI 关闭、跨渠道隔离、读取失败、保存不完整、保存后续接、临时跳过至执行等 10 个场景；另有临时跳过不读取 / 修改凭据的测试。本次不重复调用上游模型。
- 本次共 44 项前端 / 组件测试及 6 项 Rust 单元测试通过；前端、扩展构建和 Rust 格式检查通过。Windows x64 测试安装包 `TuneNest_0.1.11_x64-setup.exe` 约 2.97 MiB。QQ 与 macOS 的既有人工验收缺口仍保留。
